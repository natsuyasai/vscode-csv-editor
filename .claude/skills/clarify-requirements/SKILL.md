# 要求明確化（フロー Phase 1）

`/dev-flow` の最初のフェーズ。実装に入る前に、ユーザーの要求を **誤解なく実行可能なレベル** まで明確化する。

## 目的

- 「何を・なぜ・どこまで」やるのかを確定させる。
- 推測で進めず、**疑問があれば必ず中断して質問する**（CLAUDE.md 開発原則）。

## 手順

### Step 1: 要求の理解

1. ユーザーの要求（`$ARGUMENTS`）を読み解き、解決したい **課題・背景・目的** を把握する。
2. 関連する既存コード・既存機能を調査し、再利用できる実装・パターンがないか確認する。
3. 影響範囲（拡張機能側 `src/` / Webview 側 `webview-ui/src/`）を特定する。

### Step 2: 曖昧さの洗い出しと質問

以下の観点で曖昧な点を洗い出し、不明点があれば AskUserQuestion 等で確認する:

- **スコープ**: 対象範囲・含まないもの（非対象）
- **入出力／挙動**: 期待する動作、エッジケース、エラー時の挙動
- **UI/UX**: 表示・操作・テーマ（ライト/ダーク）への影響
- **制約**: パフォーマンス、既存仕様との互換性、データ永続化
- **優先度・完了の定義**

### Step 3: 受け入れ条件の確定

明確化した内容を **受け入れ条件（Acceptance Criteria）** として箇条書きにまとめ、ユーザーに提示して合意を得る。

```
## 受け入れ条件
- [ ] 〜が〜できる
- [ ] 〜の場合に〜となる
- [ ] （非対象）〜は今回対応しない
```

## 完了条件 / 次のフェーズ

- 受け入れ条件が確定し、ユーザーが合意した。
- → `/plan`（Phase 2: 実装プラン策定）へ進む。

## 禁止事項

- 曖昧なまま実装やプラン策定に進むこと。
- ユーザーに確認すべき仕様を独断で決めること。
